    How to capture on the FortiGate

    Start logging your SSH session first (see below), then run one of these commands in the FortiGate CLI. Press Ctrl+C to stop.

    diagnose sniffer packet any 'host 192.0.2.10' 6 0 a
    All interfaces, every packet to or from one host, Ethernet headers and interface names, absolute UTC timestamps. The best default.
    diagnose sniffer packet port1 'tcp port 443' 6 1000 a
    One interface only, HTTPS traffic, stops by itself after 1,000 packets.
    diagnose sniffer packet any 'host 192.0.2.10 and icmp' 3 50 a
    Verbose 3: same hex as 6 but without interface names. Fine for a single interface.
    diagnose sniffer packet any 'net 10.0.0.0/8 and port 53' 6 0 l
    DNS traffic with timestamps in the FortiGate's local time (l) instead of UTC (a).

    The syntax is diagnose sniffer packet <interface> '<filter>' <verbose> <count> <timestamp>. The filter uses tcpdump syntax; none captures everything. Use a count of 0 for no limit and keep filters narrow on busy firewalls — the sniffer prints every packet to your terminal.

    Saving the output to a file

    • PuTTY: before connecting, open Session → Logging, choose All session output and a log file name. Connect, run the sniffer, then drop the log file here.
    • SecureCRT: File → Log Session, pick a file, then run the sniffer.
    • macOS / Linux terminal: script sniffer.txt (macOS) or script -c "ssh -l admin 192.0.2.1" sniffer.txt (Linux) records everything shown in the terminal.
    • Short captures: just select the output in your terminal, copy, and paste it into the box above.

    Prompts, the command line, blank lines, --More--, colour codes and per-line timestamps added by your terminal are ignored automatically.

    FAQ

    What is the difference between verbose 3 and verbose 6?

    Both print every packet as hex starting from the Ethernet header (when the interface has one). Verbose 6 additionally prints the interface name and direction (port1 in), so this tool can also give you one pcap per interface. Verbose 2 and 5 start the hex at the IP header, and verbose 1 and 4 print no hex at all, so there are no bytes to convert.

    Why does Wireshark show no Ethernet (MAC) information?

    Because the sniffer output had none for those packets. That happens with verbose 2 or 5, on interfaces without a layer-2 header such as IPsec or SSL-VPN tunnels, and in a capture on any that mixes tunnels with Ethernet ports. In those cases the file is written as Raw IP. We deliberately do not invent MAC addresses — fake MACs look real in Wireshark and can send an investigation the wrong way. In a mixed capture, the per-interface downloads keep the Ethernet headers for every interface that has them.

    Is my capture uploaded anywhere?

    No. The page is static: the conversion runs in a Web Worker inside your browser and the pcap is created in memory. The code contains no upload or tracking calls, and the Content Security Policy sets connect-src 'none', so the browser refuses fetch/XHR requests from the page. You can confirm in the developer tools' Network tab that nothing is sent after the page loads. There are no cookies and no analytics.

    My log uses times like 3.462208. Is that a problem?

    No. Without the a or l option the FortiGate prints seconds since the capture started. The pcap keeps those relative times (Wireshark will show dates in 1970). If you know when the capture started, set it under Options to get real clock times.

    Some lines could not be parsed. What happened?

    The result shows how many lines failed and a few examples. Typical causes: the log starts in the middle of a packet, a hex line went missing (the packet is then left out rather than guessed), or the last packet was cut off when logging stopped (it is kept and marked as truncated in Wireshark). If the FortiGate printed "N packets received by filter", the result also compares that number with what was converted.

    Can't I just download a pcap from the FortiGate GUI?

    Often you can: recent FortiOS versions offer packet capture with pcap download in the web GUI. This tool is for when you only have CLI access, are working through a jump host or a colleague's terminal log, or already have the sniffer text and need it in Wireshark.
